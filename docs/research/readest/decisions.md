# Readest 架构与迁移决策（READER-006 T-05 / decisions）

状态：drafted · 2026-11-01。证据链：[baseline](baseline.md)（tag v0.12.16=3cc39ad7 + UI 0.12.16 portable）· [code-map](code-map.md)（引擎/服务/存储 path:line）· [ui-study](ui-study.md)（真机实测）· [capability-matrix](capability-matrix.md)（覆盖对照）。本文给推荐与有界下一步；**不冻结引擎选型**——凡原生接缝未走通整条路径探针者，一律标"候选/待验证"，先探针后立项。

## 1. 三条路线比较（计划 §5.4）

### 路线 A：AutoUI 壳 + 成熟文档引擎嵌入（web 引擎进宿主）

- **形态**：阅读表面交给 foliate-js（或同类 Web 文档引擎）在 WebView 内渲染，书库/标注/服务仍归 AutoReader .at 后端。Readest 本身即"React 壳 + foliate-js fork"的该形态（code-map §2）。
- **能换来什么**：Readest 级排版/分页/竖排/CSS/公式/固定版式（foliate-js fork 的 254 commit 差异即为工程量清单）、EPUB CFI、PDF(pdf.js)、漫画、选区/脚注弹层/朗读定位——ui-study 实测的全部阅读面能力一次到位。
- **代价与未证点**：
  1. **宿主能力**：AutoUI 需提供受控 WebView 表面（焦点、IME、选区、文本合成、滚动锚、无障碍树暴露给原生层）。这些接缝在 AutoUI 当前能力清单中无记载——**未经整条路径探针，只能判"候选/待验证"**（计划红线）。
  2. **双轨同源破坏**：AutoReader 验收是 Vue/VM 双轨同源（001~005 全部门）。WebView 表面若只在 Vue 轨成立，原生轨需另解（或接受分轨能力差异并如实声明）。
  3. **数据面不变的好处**：书库/注释/定位仍在 .at 后端（AutoReader 已有 annotation_id+锚核验+可恢复移除），引擎只换"显示+选区事件"，架构接缝清晰。
- **裁定**：**推荐作为「有界可行性探针」立项**（见 §5 P2），不作为直接实施承诺。探针通过前，禁止宣称"引擎升级已可行"。

### 路线 B：原生文档能力扩展（延续 001~005 的纯 .at 面）

- **形态**：不引引擎，按格式逐个补齐原生实现：Locator v1→v2（CFI 兼容字段）、行内子串样式（N-002-A-1 框架缺口）、PDF/漫画（原生渲染从零）、TTS/词典/翻译（宿主/服务面逐个接）。
- **优势**：双轨同源保持；数据与验收体系（隔离测试+永久验收入口）直接延续；AutoReader 已交付面（导入事务/锚核验/诚实拒绝/可恢复移除/双端 UI 驱动）无需返工。
- **代价**：Readest 级排版（出版物 CSS、竖排、分页对齐、公式）在纯 .at + 原生 widget 路线下的工程量无上界；PDF 单项即一个大计划群；**覆盖速度远慢于路线 A**，且矩阵中 C02 深排版域多数行会长期停在"缺失"。
- **裁定**：作为**书库/标注/定位/日用面的主干**继续（这些域 AutoReader 架构已占优，见 §2），但不作为排版/多格式的 Monaco 承诺。

### 路线 C：外部应用过渡（必要时的过渡接入）

- **形态**：AutoReader 保留书库与知识流，格式阅读外包给外部成熟阅读器（如直接联动 Readest）。
- **评估**：矩阵 C04 全格式能力即刻"可用"，但（1）不构成 AutoReader 自身覆盖（计数分母不因此变色）；（2）数据所有权/标注回流需要双向迁移面；（3）第三方应用许可与分发（Readest 为 AGPL）需独立评估；（4）与"完整个人电子书阅读器"的产品定位冲突。
- **裁定**：**不推荐**为主路线；仅当个别长尾格式（如特定漫画/古早格式）自建成本过高时，作为标注"过渡"的补充面，且必须显式记录许可边界。

### 推荐

**B 为主干 + A 为有界探针 + C 仅长尾过渡**。书库、注释、定位、导出、恢复、诚实拒绝这些 AutoReader 已有优势域继续原生深化；阅读表面（C02 排版、C04 多格式渲染）走探针决定 A 是否成立；探针失败则 B 路线在 C02/C04 的覆盖目标按证据下调并如实重排路线。

## 2. 定位与注释迁移设计（对 ui-study/code-map 的直接回应）

- **现状对照**：Readest 锚 = EPUB CFI + 字符偏移（真机实证 `epubcfi(/6/4!/4/12,/1:7,/1:31)`，导出含 `readest://…?cfi=` 深链）；AutoReader 锚 = Locator v1（章+段+para_text 逐字全文）+ 注释 occurrence 段内出现序（002 交付）。两者都解决了"重复句消歧"——AutoReader 用 occurrence 计数，Readest 用 CFI 偏移（另有"应用到所有匹配"批量面）。
- **迁移原则**：**不丢任何用户标注**。Locator v1→v2 采用"兼容读取 + 字段扩展"：保留 chapter/paragraph/para_text 逐字锚作为**内容证明与失配仲裁**（跨引擎仍可重定位），新增可选 `cfi`/`page` 字段承载格式定位信息；import_version 升版；旧库逐字兼容（001 的 refuse-to-load 纪律不放松）。
- **迁移步序**（进后续实施计划，不在本研究实施）：①读侧兼容 v1/v2 双形；②新注释写 v2（带 cfi 或按格式）；③旧记录惰性升级（打开书时后台补 cfi，失败保留 v1 并标待补）；④备份/回退沿写协议（.bak/暂存/读回校验）。
- **失配语义**：沿用 002 的 `needs_relocate` 诚实态（原摘录保留、绝不静默跳错）——与 Readest 的 deletedAt 静默 tombstone 形成差异，AutoReader 语义**保留不放宽**。

## 3. 书库差距与日用面

- Readest 书库强项（矩阵 C01）：书封/元数据编辑、分组/标签、排序/筛选（页数、自然序）、跨书搜索、Demo 引导、云备份。AutoReader 已有强项：导入事务诚实性（sha256 去重+逐字核对）、**可恢复移除**（Readest 无恢复入口）、10MiB→30MiB 长文门、双端验收驱动。
- **建议优先补**（C01/C03 日用，路线 B 内）：书封（导入期生成+存储）、分组/标签、书架排序筛选、跨书搜索（后端段扫描已具备，缺聚合面）、批量导入。
- **不采纳**：Readest 的软删不可恢复语义；匿名 Demo 书注入（AutoReader 空态以本地示例语料引导即可，且须用户可见为示例）。

## 4. 服务面（TTS/翻译/词典/同步/书源）

- **共性结论**：Readest 服务面 ~10% 能力被 Plus/Pro 账号/外部服务闸住（矩阵计数节）；免费本地面（本地 TTS 语音、本地词典文件、OPDS 目录）与付费面分层清晰。AutoReader 应**按"本地优先、远程显式触发"总设计原则逐服务接**，每个服务一个数据流向/凭据/离线三问（总设计 §7 已立）。
- **TTS**：Readest 桌面免费面 = 系统 Web 语音（真机实测朗读+句级导航）；AutoReader 对应面是 AutoUI/宿主 speech 能力（框架 owner，先实查能力清单再立项）。
- **翻译/词典**：Readest 服务端 key 池代理（DeepL/Yandex）+ 本地 MDict；AutoReader 若接，凭据存储与配额面独立设计，**不内嵌第三方 key**。
- **同步**：Readest 用 Supabase + HLC CRDT 副本引擎（code-map §8）——复杂度足够独立立项；AutoReader 短期目标是**本地备份/恢复**（已有写协议可复用），跨设备同步单独立项且默认不上传整库。
- **书源**：OPDS 客户端是标准协议面，可独立小计划；"网页剪藏/网文"涉及登录态爬取，暂不对标（法律/稳定性边界在矩阵登记）。

## 5. 首批后续计划建议（AC-08；不取号、不自动实施）

| 序 | 候选计划 | owner 仓 | 依赖 | 范围要点 | 验收任务（草案） | 优先级理由 |
|---|---|---|---|---|---|---|
| P1 | Locator v2 与注释锚扩展 | auto-reader | 无（纯现有面） | cfi/page 可选字段+迁移+兼容读取+诚实失配；导出加稳定引用行 | 旧库全量迁移零丢失；v1/v2 双形读写回环；重复句 occurrence 语义保持；跨"换布局/换引擎模拟"重定位 | 一切引擎/格式工作的地基；独立可交付 |
| P2 | 阅读引擎嵌入可行性探针 | auto-ui（框架 owner）+ auto-reader 消费 | 无（P1 并行） | 最小 WebView 表面：装载 foliate-js 上游版打开一本 EPUB，焦点/IME/选区/滚动/无障碍五接缝各一条真机路径 | 探针报告：五接缝各 pass/fail+证据； fail 项给框架侧最小修复建议；**不实施产品功能** | 决定路线 A 生死；避免全量押注 |
| P3 | 书库日用面 | auto-reader | 无 | 书封/分组/标签/排序筛选/跨书搜索聚合/批量导入 | 每能力双端 UI 驱动用例+数据面 spec 增量 | 用户可见收益最大、风险最低 |
| P4 | 导出与互操作增强 | auto-reader | P1 | Markdown 导出补稳定引用（annotation 稳定 ID 已有）；评估 readest:// 类自协议深链（auto-reader://） | 导出可回跳锚实测；JSON 导出格式 spec | 与 P1 协同小成本 |
| P5 | TTS 本地面 | auto-ui（speech 面）+ auto-reader | P2 结论（若 A 成立则随引擎；否则宿主 speech） | 系统 TTS 朗读+句级高亮+播放控制 | 本地语音朗读一本中文 EPUB 的句级导航真机验收 | C05 最高频辅助面 |
| P6 | PDF/漫画评估（探针后） | 视 P2 | **P2 通过** | 引擎内 pdf.js/漫画渲染面评估与范围界定 | 评估报告（不实施） | 依赖引擎结论，防无效立项 |

- 排序原则：P1/P3 并行先行（无依赖、各自独立验收）；P2 探针尽早（决定 C02/C04 的路线）；P5/P6 严格排在依赖结论之后。
- **明确不做**（本轮）：取计划号、自动创建计划、任何产品功能实施、同步服务搭建、账号体系。

## 6. 未决问题（留用户裁定或后续证据）

1. 若 P2 探针失败（宿主接缝不可行），C02 深排版与 C04 多格式的目标是否下调或转 C 路线过渡——**影响目标范围，留用户裁定**（触发条件=探针 fail）。
2. 覆盖率目标阈值：分母与计数规则已立（矩阵计数节），**目标百分比建议待首批计划落地后再定**，避免以未验证能力充数。
3. 自有 deep-link 协议（类 readest://）是否纳入 OS 级协议注册——牵涉 AutoOS 公共通信，留系统协同。
