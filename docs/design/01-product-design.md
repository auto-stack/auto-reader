# AutoReader：产品总设计与 Readest 覆盖目标

状态：proposed（目标设计）；更新：2026-11-01；目标修订：Readest coverage v1。

用户于 2026-11-01 明确：AutoReader 要复刻 Readest 开源项目的绝大多数能力。工作顺序为先调整总设计与路线，再通过独立计划详细调研其文档、代码和实际 UI；根据调研再次修订设计与路线，之后确定实施计划。本文是调研前的目标基线，不预定阅读引擎、不代表功能已经交付。

现实现以 docs/specs/reader 下各模块规范和实际验收为准；后续调研入口为 [READER-006](../plans/006-readest-deep-research.md)，阶段安排见[路线图](../roadmap-v0.6.md)。本文替代旧版目标排程；历史基线通过 Git 和归档计划追溯。

## 1. 产品定位与成功定义

AutoReader 是以本地阅读为基础的完整个人电子书阅读器。以 Readest 为主要产品、交互和工程参照，逐步覆盖它的主要阅读、书库、标注、多格式、辅助阅读、书源与同步能力，并接入 AutoOS 的 Notes/Jade 知识流。

“覆盖绝大多数能力”必须落实为可核查的功能清单与真实用户任务。研究时固定 Readest 提交、发布版本、文档快照日期和 UI 构建身份，区分已发布能力、主分支独有能力、计划中功能及仅有宣传描述的能力。以已核实的已发布能力作为主要对标分母；主分支新增能力另列候选，不混计。

调研后逐项给出 AutoReader 的完整覆盖、部分覆盖、缺失、待验证或经裁定排除状态；部分覆盖列出差距。覆盖比例的计数单位、权重和目标阈值在调研收口时提出依据，不能事先编造百分比，也不能通过拆细已有功能或删除难项提高成绩。核心日用任务单独验收，不能用外围功能抵消阅读核心缺失。

产品功能覆盖与平台覆盖分开：Windows 和现有 Vue/原生 VM 路径是当前验证基础；Linux 仍等待 Nix＋COSMIC 发行版基础。移动端、Web、电子墨水设备适配纳入调研，但覆盖阅读能力不自动等于同步交付全部平台。DRM、商业书店、账号运营和付费云服务需独立界定，不能据此缩减本地阅读能力。

## 2. 已交付基线与关键差距

截至 2026-11-01，READER-001～005 已交付归档；不重开旧计划，新增目标另立计划。

| 能力 | 已观察的交付范围 | 与新目标的差距/边界 |
|---|---|---|
| 真实书库 | TXT/Markdown 导入、受管原件、去重、书库持久化、阅读恢复 | 文件选择/批量导入、书封、组织与检索体验需进一步对标 |
| EPUB | 无 DRM EPUB3 最小 profile；spine/目录、图片、书内链接与脚注往返 | 章 XHTML 转文本行和图片行；不等于保留 HTML/CSS、复杂表格/公式/竖排或嵌入字体 |
| 阅读设置 | 字号、行距、列宽、light/sepia/dark 主题与偏好保存 | 完整字体控制、分页/滚动、出版物样式与辅助功能需调研 |
| 标注与检索 | 段锚、摘录、书签/高亮/批注、书内精确子串搜索、Markdown 导出 | 高亮为段级标记；无完整划词选区与行内子串样式；跨书检索尚不完整 |
| 定位 | 章号、段号、原文核验；恢复与失配提示 | 自定义 Locator v1 不等于 EPUB CFI；引擎升级需兼容与迁移 |
| 双端验收 | 005 聚合门与真实 UI 驱动已交付 | 原生 UI 写传输、scroll-pane 自动化按压有具名缺口，不等于所有原生交互完整覆盖 |
| 系统与平台 | 可独立运行 | Notes/Jade 真实交接与 OS 装配另属系统协同；Linux 前置未就绪 |

来源：[真实书库](../specs/reader/real-library.md)、[EPUB](../specs/reader/epub-reflow.md)、[注释](../specs/reader/reading-annotations.md)、[独立阅读](../specs/reader/standalone-reading.md)。这些边界描述当前实现，不限制长期目标。

## 3. 对标能力域

以下是调研清单的领域入口，并非声明 Readest 的每一项均已发布。006 从文档、代码和 UI 交叉核实，补充遗漏、记录平台差异并细化为稳定功能 ID。

| 域 ID | 能力域 | 需要核实与设计的范围 |
|---|---|---|
| C01 | 文件与书库 | 文件选择/拖放/批量与 URL 导入、元数据/书封、去重、分组/标签、排序过滤、删除恢复、备份与迁移 |
| C02 | 阅读与排版 | 滚动/分页、多列、字体/字号/行距/边距、主题/出版物 CSS、图片放大、表格/代码/公式、CJK/竖排、脚注与导航 |
| C03 | 选区、标注与定位 | 选择/复制、行内多色高亮、书签/批注、笔记本、跨章查找、格式定位器、回跳、导出与互操作 |
| C04 | 多格式 | EPUB、PDF、MOBI/AZW3、FB2、CBZ、TXT、HTML/Markdown 等候选；分别核对真实可读、可选、可标注的深度 |
| C05 | 深度与辅助阅读 | 查词/百科、翻译、TTS 与朗读定位、双书对照、统计、专注辅助、校对、无障碍；存在性与范围待核实 |
| C06 | 书源与传输 | OPDS、calibre/自建书库、在线导入、局域网传书/设备互通；辨别公开协议与服务依赖 |
| C07 | 同步与生态 | 书籍/位置/偏好/注释同步、离线队列、冲突与备份、自托管/第三方服务、外部导出、平台差异 |
| C08 | AutoOS 知识流 | 带原文、稳定来源与附件的 Notes/Jade 交接；不把未交付系统服务作为本地读书前置 |

PDF、TTS、对照阅读、书源和同步由旧版的笼统后置调整为正式对标域；实施优先级在调研后确定。OCR、AI 问答等相邻功能先核实与基准的关系，再标注为对标项或 AutoReader 扩展项。

## 4. 架构原则与待决路线

### 4.1 分层与所有权

- 书库与资产层拥有稳定 book_id、源版本指纹、受管原件、元数据、索引和迁移；阅读引擎不能各建一套书库。
- 文档与引擎适配层按格式提供资源、目录、排版、选区、搜索和定位；EPUB 与 PDF 可使用不同引擎，但需协调位置和能力声明。
- 阅读与交互层由 AutoUI 承载工作区；渲染表面、输入、选区、焦点、无障碍与原生合成的接缝必须实证。
- 标注与引用层拥有 annotation_id、原句/上下文、源版本和格式定位器；独立于显示样式，支持迁移、导出和明确失配。
- 服务适配层隔离词典、翻译、TTS、OPDS、同步与跨 app 交接；离线时核心阅读和本地标注可用，远程动作明确触发。

已有代码位于 src/back/{library,epub,annotations,importers}.at 与 src/front/pages/reading_page.at 等；上述是职责划分，不是已存在的新目录，也不强制未来的文件拆分。

### 4.2 引擎决策保持开放

调研比较 AutoUI 外壳加成熟文档引擎、扩展原生富文本/文档能力，以及必要时的外部应用过渡接入。Readest、其 foliate-js fork、上游 foliate-js 和 PDF 等依赖分别追溯版本与职责，不能把复用一个库等同于获得整个产品。

不在调研前决定重写排版器或移植 React/Tauri 界面。比较功能覆盖、Vue/VM 接缝、选区与定位、性能、离线与资源隔离、许可/分发要求、维护成本和替代路径。只在浏览器内演示不构成原生可行性结论。

应用业务保持纯 .at，不改生成 Rust/Vue。若需新宿主能力，先核实已有能力与实际 owner，再由框架仓另立最小前置计划；006 不直接修改框架代码。

## 5. 数据、兼容与知识流

保留书籍身份、受管原件和注释身份。下一代位置模型支持格式定位信息与原文核验：EPUB 评估 CFI/资源与范围，PDF 评估页、坐标与文本锚；百分比只作展示。换字体、布局或引擎后回到同一内容；源版本变化、多义命中或失配要保留原摘录并提示处理。

调研给出 Locator v1、段级注释和现有缓存的迁移建议，包括兼容读取、备份、失败回退和不支持状态；不得因换引擎丢弃用户标注。具体 schema、事务与资源预算经后续实施验证再进入 Spec，不把目标结构写成当前协议。

Notes/Jade 围绕稳定实体引用、资产引用、来源定位、版本化 CaptureEnvelope 和持久化回执设计。历史 EntityRef、AssetRef、SourceRef、CaptureReceipt 保留为语义候选，不宣称是已实现系统 API。幂等、附件接收、离线与冲突由后续系统契约确认，不恢复 002-B。

系统通道复用 AutoOS 公共通信和 DevTools，参见[通信 RFC](https://github.com/auto-stack/auto-os/blob/main/docs/design/strategy/auto-app-communication-v0.6.md)与 [DevTools RFC](https://github.com/auto-stack/auto-os/blob/main/docs/design/strategy/system-devtools-v0.6.md)；落地状态需执行时核验。应用保留独立本地导出能力。

## 6. UI/UX 目标与验证任务

书库支持继续阅读、真实文件导入、搜索和组织；阅读以正文为中心，目录/搜索/注释侧栏与偏好按需展开。选区支持高亮、批注、复制和适用的查词/翻译；双书对照、朗读与网络能力不挤占默认界面。

使用相同任务与自制/可再分发语料观察 Readest 与 AutoReader：导入→目录/脚注往返→改字号或模式→选区/标注→搜索回跳→关闭重开→导出。PDF、漫画、对照、TTS、OPDS 和同步分别增加适合该域的任务，不用 EPUB 单一任务代表全部格式。

同时研究键盘、IME、窄屏、大字号、深色主题、读屏、空状态、加载/错误、损坏资源、离线/无账号状态。真实 UI 证据记录版本、步骤、预期/实际及截图/日志索引；外观相似不代表业务与恢复正确。未运行的功能标记未验证，代码存在不能代替 UI 证据。

## 7. 质量与发布约束

保留 001～005 的隔离测试和永久验收入口。后续方案明确中文/混排、脚注、图片表格、长章、重复句、损坏出版物、离线、重启与迁移的边界。

性能先按固定机器、构建、语料和冷热状态实测，再设可解释目标；旧版未经本轮核实的延迟数字不沿用为已达成指标。各格式分别说明支持与拒绝方式，不能静默丢内容后宣称兼容。

出版物资源限制在对应书籍的受管范围，不执行 EPUB 活动脚本或自动加载远程内容；路径、压缩与解码预算在实际引擎方案中明确。导入/加载失败不制造假书，大任务可取消且不冻结界面；移除书目与处理用户原文件分别设计，保留恢复和错误诊断路径。

远程翻译、TTS、同步和 AI 的服务依赖、数据流向、凭据存储独立设计；默认不上传整库。AI 派生内容与作者原文区分并保留来源，未配置服务时本地阅读仍可完成。

## 8. 研究到实施的决策门

当前唯一新增计划是 READER-006：交付完整对标矩阵、文档/代码/UI 证据、引擎与迁移建议，以及调研后本文与路线图的二次修订。先完成研究再排序实施，不把“引擎升级”“PDF”“TTS”等候选标题当作已批准工程方案。

研究收口时确定首批计划的范围、依赖、验收、优先级和 owner；可行性未定者先列有界探针。客观缺证保留范围与阻塞，不通过排除能力宣布调研完成。后续正式计划据结论另行取号，执行与复审遵循 auto-plan 流程。

## 9. 工程与交付

使用 D:/autostack/auto-reader 独立 clone 的 main 进行编辑与顺序复审，一 app 一写入者；AutoOS apps/auto-reader 仅为组合 pin。不得创建 junction/symlink。Readest 需要本地研究时使用独立真实 clone，不在产品仓或组合子模块中开发竞品。

本次为目标设计与研究计划准备，不实施研究、不改当前 Spec/旧 ledger、不更新 OS gitlink。后续研究也不直接交付产品功能；应用交付与 OS 装配分别管理。
