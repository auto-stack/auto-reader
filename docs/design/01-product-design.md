# AutoReader：产品总设计与 Readest 覆盖目标

状态：proposed（目标设计）；更新：2026-11-01；目标修订：**Readest coverage v3**（006 交付后的设计收敛与后续顺序讨论）。

用户于 2026-11-01 明确：AutoReader 要复刻 Readest 开源项目的绝大多数能力。工作顺序为先调整总设计与路线，再通过独立计划详细调研其文档、代码和实际 UI；根据调研再次修订设计与路线，之后确定实施计划。**READER-006 详细调研已交付**：发布分母 257 项能力逐行对照见[能力矩阵](../research/readest/capability-matrix.md)，真机实测见 [UI 研究](../research/readest/ui-study.md)，综合结论与假设核对见[调研报告](../research/readest/report.md)。

现实现以 docs/specs/reader 下各模块规范和实际验收为准。[006 决策](../research/readest/decisions.md)中的P1~P6为研究候选；用户现同意先起草P2，唯一正式合同为 [auto-ui/PLAN-026](https://github.com/auto-stack/auto-ui/blob/master/docs/plans/026-reader-engine-embedding-and-locator-probe.md)（drafting/r1、0/10，暂不实施）。其余候选未取号，本文替代旧目标排程，历史基线可通过Git/归档追溯。

## 1. 产品定位与成功定义

AutoReader 是以本地阅读为基础的完整个人电子书阅读器。以 Readest 为主要产品、交互和工程参照，逐步覆盖它的主要阅读、书库、标注、多格式、辅助阅读、书源与同步能力，并接入 AutoOS 的 Notes/Jade 知识流。

“覆盖绝大多数能力”已有固定研究基线：**v0.12.16 发布能力对照 257 行**（全量 259 行：C01 55 / C02 60 / C03 28 / C04 15 / C05 39 / C06 23 / C07 39；C04-010 主分支候选与 C05-035 code-only 不计入；主分支候选 31 项另列），稳定 ID 见[能力矩阵](../research/readest/capability-matrix.md)。这是发布功能盘点，不是 257 项逐条实机通过证明，更不是 AutoReader 已覆盖的数量。其中约 25 项带账号、付费或外部服务条件；矩阵中 AutoReader 的 102 行“待验证”不能一概算缺失，4 行“排除（需裁定来源）”也不等于用户已经同意排除。

覆盖管理分为固定发布对照、AutoReader 实证状态和核心任务三层。每份后续计划绑定具体 RDT 功能 ID，区分完整/部分/缺失/待验证及平台条件；只有实测达到该项范围才计完整，不因存了字段或出现入口就计通过。现阶段不声称覆盖百分比；在引擎探针和首批受影响能力核对后，先为后续里程碑提出覆盖范围与验收目标，再实施，不能等实现结束后倒定目标。

Readest 的 EPUB 选区、批注、重复句搜索、重开恢复和导出链路有实机与复审证据；对话框导入仍有受管副本缺失/静默失败，阅读曾通过 argv/open-with 路径继续。PDF 打开/翻页/缩放有证据，**选区与标注成功链路未获充分实机确认**；双书对照、部分格式、读屏与服务成功面仍有缺证。后续验收不能从“核心全绿”概括语推导所有路径都可用，详见 [UI 研究](../research/readest/ui-study.md) 的具体任务记录。

产品功能覆盖与平台覆盖分开：Windows 和现有 Vue/原生 VM 路径是当前验证基础；Linux 仍等待 Nix＋COSMIC 发行版基础。移动端、Web、电子墨水设备适配纳入调研，但覆盖阅读能力不自动等于同步交付全部平台。DRM、商业书店、账号运营和付费云服务需独立界定，不能据此缩减本地阅读能力。

截至 2026-11-01，READER-001～005 已交付归档；不重开旧计划，新增目标另立计划。

| 能力 | 已观察的交付范围 | 与新目标的差距/边界 |
|---|---|---|
| 真实书库 | TXT/Markdown 导入、受管原件、去重、书库持久化、阅读恢复 | 文件选择/批量导入、书封、组织与检索体验需进一步对标 |

## 4. 架构原则与待决路线

### 4.1 分层与所有权

- 书库与资产层拥有稳定 book_id、源版本指纹、受管原件、元数据、索引和迁移；阅读引擎不能各建一套书库。
- 文档与引擎适配层按格式提供资源、目录、排版、选区、搜索和定位；EPUB 与 PDF 可使用不同引擎，但需协调位置和能力声明。
- 阅读与交互层由 AutoUI 承载工作区；渲染表面、输入、选区、焦点、无障碍与原生合成的接缝必须实证。
- 标注与引用层拥有 annotation_id、原句/上下文、源版本和格式定位器；独立于显示样式，支持迁移、导出和明确失配。
- 服务适配层隔离词典、翻译、TTS、OPDS、同步与跨 app 交接；离线时核心阅读和本地标注可用，远程动作明确触发。

已有代码位于 src/back/{library,epub,annotations,importers}.at 与 src/front/pages/reading_page.at 等；上述是职责划分，不是已存在的新目录，也不强制未来的文件拆分。

### 4.2 引擎决策（006 调研后裁定）

调研比较了三条路线并给出裁定（完整论证见[决策](../research/readest/decisions.md) §1）：

- **路线 B（应用数据与服务主干）**：书库/标注/定位/导出/恢复继续由纯 .at 应用拥有，沿用导入事务、锚核验、可恢复移除与双端验收。“主干”不代表已经决定用原生 widget 自研 Readest 级排版器。
- **路线 A（有界探针）——AutoUI 壳 + 成熟文档引擎嵌入**：阅读表面（C02 排版、C04 多格式渲染）是最大差距，其本质是"一个 254-commit 深度 fork 的文档引擎 vs 自研渲染"。Web 引擎进宿主的五接缝（焦点/IME/选区/滚动锚/无障碍）**未经探针前只判"候选/待验证"**；探针由框架仓 owner 立项（P2），通过前不宣称引擎升级可行。
- **路线 C（仅长尾过渡）——外部应用过渡**：不作为主路线；仅个别自建成本过高的长尾格式可作显式标注的过渡面，须记录许可边界（Readest 为 AGPL）。

Readest、其 foliate-js fork（上游 + 254 commits，固定版式 261→2148 行、分页器重写、pdf.js 改造）、上游 foliate-js 与 pdf 等依赖已分别追溯（[代码地图](../research/readest/code-map.md) §3）；复用上游库不等于获得 Readest 阅读面。

**下一步推荐先验证路线 A 的宿主接缝**。探针由实际宿主能力 owner 主导，AutoReader 提供最小消费者；先核对已有 WebView/输入/无障碍能力，缺什么再提出最小宿主变更。上游 foliate-js 可作轻量对照，但正向样本应包含 006 固定的 Readest fork 或明确列出与它的能力差异，不能用上游“打开一本书”推导 Readest 级兼容。

探针从受管 EPUB 的真实读取开始，贯穿样式/图像/脚注渲染、真实选择重复句指定一处、选区事件与定位信息回传 .at、保存、退出重开后恢复同一原文。焦点/中文 IME、滚动与重排定位、原生合成、无障碍分别给结果；Vue 与原生 VM 分别验证，不用外部浏览器窗口代替宿主嵌入。探针只证明覆盖到的样本与接缝，不宣称全格式或发布级质量。

探针若失败，保留失败接缝的最小复现、owner 与修复成本，比较宿主修复和其他引擎/原生文档方案；**不自动下调 C02/C04 覆盖目标**。目标变化另据证据讨论，失败也不阻止 PDF/漫画替代路线评估。

不在探针前决定重写排版器或移植 React/Tauri 界面。应用业务保持纯 .at，不改生成 Rust/Vue。若需新宿主能力（WebView 表面、speech 等），先核实已有能力与实际 owner，再由框架仓另立最小前置计划；006 不直接修改框架代码。

## 5. 数据、兼容与知识流

保留书籍身份、受管原件和注释身份。下一代位置模型支持格式定位信息与原文核验：EPUB 评估 CFI/资源与范围，PDF 评估页、坐标与文本锚；百分比只作展示。换字体、布局或引擎后回到同一内容；源版本变化、多义命中或失配要保留原摘录并提示处理。

**006 调研后的迁移原则**（[决策](../research/readest/decisions.md) §2）：Readest 使用 EPUB CFI+字符偏移，AutoReader 使用 Locator v1 段锚与 occurrence 段内出现序；保持书籍身份、annotation_id、原句与重复句消歧语义，采用兼容扩展而非替换旧锚。002 的 needs_relocate 语义保留，失配不能静默删注释或跳到别处。

**v3 对候选 P1 的细化**：CFI 必须来自对应版本 EPUB 的真实文档树/引擎范围；当前扁平化文本与章段号不足以证明可逆映射。PDF 页/坐标锚又是另一种格式语义。因此不先把 cfi/page 两个可选字段当成已经完成的定位升级，也不承诺旧记录一打开就能自动补 CFI。

可先核对现有定位/注释 schema、旧库样本和兼容边界；待探针明确引擎的资源身份、range/CFI 生成与解析、事件回传后，再冻结 Locator v2 与版本策略。书籍导入版本、阅读状态版本和注释 schema 分开判定影响，不默认统一升级 import_version。迁移验收覆盖 v1 兼容读、v2 回环、重复句/跨行、换布局与重启、备份/回退以及无法映射时保留 v1 并明确失配；无真实转换器不做假升级。

Notes/Jade 围绕稳定实体引用、资产引用、来源定位、版本化 CaptureEnvelope 和持久化回执设计。历史 EntityRef、AssetRef、SourceRef、CaptureReceipt 保留为语义候选，不宣称是已实现系统 API。幂等、附件接收、离线与冲突由后续系统契约确认，不恢复 002-B。

系统通道复用 AutoOS 公共通信和 DevTools，参见[通信 RFC](https://github.com/auto-stack/auto-os/blob/main/docs/design/strategy/auto-app-communication-v0.6.md)与 [DevTools RFC](https://github.com/auto-stack/auto-os/blob/main/docs/design/strategy/system-devtools-v0.6.md)；落地状态需执行时核验。应用保留独立本地导出能力。

## 6. UI/UX 目标与验证任务

书库支持继续阅读、真实文件导入、搜索和组织；阅读以正文为中心，目录/搜索/注释侧栏与偏好按需展开。选区支持高亮、批注、复制和适用的查词/翻译；双书对照、朗读与网络能力不挤占默认界面。

使用相同任务与自制/可再分发语料观察 Readest 与 AutoReader：导入→目录/脚注往返→改字号或模式→选区/标注→搜索回跳→关闭重开→导出。PDF、漫画、对照、TTS、OPDS 和同步分别增加适合该域的任务，不用 EPUB 单一任务代表全部格式。

同时研究键盘、IME、窄屏、大字号、深色主题、读屏、空状态、加载/错误、损坏资源、离线/无账号状态。真实 UI 证据记录版本、步骤、预期/实际及截图/日志索引；外观相似不代表业务与恢复正确。未运行的功能标记未验证，代码存在不能代替 UI 证据。

## 7. 质量与发布约束

保留 001～005 的隔离测试和永久验收入口。后续方案明确中文/混排、脚注、图片表格、长章、重复句、损坏出版物、离线、重启与迁移的边界。

性能先按固定机器、构建、语料和冷热状态实测，再设可解释目标；旧版未经本轮核实的延迟数字不沿用为已达成指标。各格式分别说明支持与拒绝方式，不能静默丢内容后宣称兼容。

出版物资源限制在对应书籍的受管范围，不执行 EPUB 活动脚本或自动加载远程内容；路径、压缩与解码预算在实际引擎方案中明确。导入/加载失败不制造假书，大任务可取消且不冻结界面；移除书目与处理用户原文件分别设计，保留恢复和错误诊断路径。

远程翻译、TTS、同步和 AI 的服务依赖、数据流向、凭据存储独立设计；默认不上传整库。AI 派生内容与作者原文区分并保留来源，未配置服务时本地阅读仍可完成。

## 8. 研究到实施的决策门

READER-006 已归档，其 P1~P6 建议保留为来源；本次 v3 讨论建议按以下决策门推进，具体范围见[路线图](../roadmap-v0.6.md)：

1. **已建立正式合同：auto-ui/PLAN-026 阅读引擎嵌入与定位回传探针（原P2）**，UI主导、Reader消费，0/10且暂不实施，优先消除宿主与真实定位回传的不确定性。
2. **同阶段可准备**：P1 的现有锚/迁移契约核对，以及 P3 中小范围日用改进；本 app 一写入者，准备工作按序推进，不承诺多计划同时写同一 clone。
3. **探针结论后**：决定实际阅读表面路线，再确定 Locator v2 实施和完整 EPUB 选区/排版闭环，避免只交字段没有用户能力。
4. **之后分域推进**：PDF/漫画、TTS、导出互操作；PDF 评估依赖探针结论而非一定通过。TTS 宿主能力核对可先做，句级定位与高亮随实际阅读模型验收。自定义 URI 注册与 .at 数据导出分开，前者由 OS 协同。
5. **保留完整长期范围**：其他格式、双书对照、词典/翻译、OPDS 与本地备份，再到跨设备同步；各自绑定矩阵 ID、服务条件和验收，不因不在首批而排除。

本次只起草UI/026并同步两仓导航，不实施功能，不改当前Spec、既有研究报告或归档006；Reader不另取号。框架静态核查已发现选择复制/Rich/远程帧，后续不能将它们误写为不存在，也不能将其等同完整DOM/CFI表面。双端门与go/no_go判据以026合同为准。
